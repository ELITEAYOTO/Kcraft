# KCraft V2.2 — Compiled Recipe Engine

## But

V2.2 ne remplace pas encore le matcher live.

Elle transforme chaque `CraftRecipe` mutable/configurable en un
`CompiledRecipe` immutable, une seule fois au boot/reload.

Le but est de déplacer le travail statique hors du hot path avant V2.3.

## Ce qui est précompilé

Pour chaque recette :

- type SHAPED / SHAPELESS ;
- table requise ;
- dimensions du pattern ;
- nombre de slots occupés ;
- quantité totale requise ;
- cellules non vides du pattern ;
- ingrédients shapeless déjà triés par spécificité ;
- Material distincts ;
- quantité requise par Material ;
- contraintes NBT ;
- présence d'identité nom/lore/NBT ;
- score de spécificité ;
- nombre de résultats ;
- somme des poids des résultats ;
- signature primaire grossière.

Pour chaque ingrédient :

- Material ;
- data ;
- amount ;
- nom déjà colorisé ;
- lore déjà colorisé ;
- NBT copié en map immutable ;
- strict-material ;
- allow-custom-items ;
- score de spécificité.

## Gain déjà préparé

Le matcher V1 shapeless fait actuellement un tri de ses ingrédients à chaque
tentative de match.

En V2.2, l'ordre est calculé une seule fois.

Le matcher V2.3 utilisera directement cette liste.

## Catalogues

```text
RecipeCatalog
  CraftRecipe historiques
       |
       v
CompiledRecipeCatalog
  CompiledRecipe immutables
       |
       +-- by id
       +-- by table
```

`recipesForTable(tableId)` est donc déjà O(1) pour récupérer le bucket d'une
table. En V2.3 on ajoutera l'index par fingerprint de matrice à l'intérieur de
ces buckets.

## Important

Le runtime de craft utilise encore `CraftMatrixTransaction` en V2.2.

Donc les performances live ne doivent pas encore être benchmarkées comme la
nouvelle architecture finale.

Le gros basculement arrive en V2.3 :

```text
ItemSnapshot
MatrixFingerprint
RecipeIndex
RecipeMatcher sans clone
```
