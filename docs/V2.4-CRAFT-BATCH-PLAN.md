
## Pourquoi PreCraftEvent/executeCraft restent par craft

V2.4 preserve encore le contrat API actuel :

- success-rate individuel ;
- actions par craft ;
- PostCraftEvent individuel ;
- cancellation PreCraftEvent.

Le batch event unique arrive en V2.6 avec le contrat Kjobs/fork.

Ainsi V2.4 retire deja le cout inutile de matching/hooks/clone sans casser le
comportement de succes aleatoire et les integrations existantes.

## SHAPED

Le planner resout l'origine et le mirror sur les ItemSnapshot V2.3, puis
travaille uniquement avec des quantites `int`.

## SHAPELESS

A chaque craft planifie, le backtracking travaille sur :

- les memes ItemSnapshot ;
- les memes NBT/meta caches ;
- un `usedMask` int ;
- un `int[] remaining`.

Aucun nouvel ItemStack/NBTItem n'est cree par craft.

Cette simulation permet aussi de changer l'affectation des stacks entre deux
crafts, donc le nombre de crafts planifie n'est pas artificiellement limite par
l'affectation du premier craft.
