# KCraft V2.1 — Foundation

## Objectif

V2.1 pose les frontières nécessaires avant d'optimiser réellement le matching:

- `schema_version: 2`
- configuration principale stricte
- `RuntimeConfig` immutable
- suppression des namespaces GUI legacy
- suppression des options V1 qui donnaient l'impression d'un cache de matching sans en être un
- `RecipeCatalog` immutable
- validation structurelle des recettes
- tailles de tables limitées à `3x3`, `4x4`, `5x5`
- fail-fast au boot/reload si la configuration ou les recettes sont incohérentes

## Ce que V2.1 ne change PAS encore

Le moteur historique `CraftManager.findMatchingRecipe()` reste actif. Le changement volontairement profond arrive ensuite:

- V2.2: `CompiledRecipe`
- V2.3: `RecipeIndex`, `MatrixFingerprint`, matching sans clone
- V2.4: `CraftBatchPlan`
- V2.5: coalescing GUI / preview lock
- V2.6: API/event batch Kjobs

## Compatibilité

- Java 8
- CraftBukkit/Spigot/Panda/Khope `v1_8_R3`
- aucune modification du fork dans cette phase
- PlaceholderAPI Maven/systemPath laissé tel quel dans le `pom.xml`

## Important pour config.yml runtime

KCraft utilise `saveDefaultConfig()`: une ancienne config déjà présente dans `plugins/Kcraft/config.yml` n'est pas remplacée automatiquement.

Pour le premier test V2.1, sauvegarder l'ancienne config puis mettre la nouvelle `config.yml` V2.1 dans `plugins/Kcraft/` ou supprimer l'ancienne sur le serveur de test afin que la V2 soit exportée.

## Validation

Une erreur V2 est bloquante, par exemple:

- `schema_version` différent de 2
- ancien bloc racine `gui:`
- taille `7x7` / `9x9`
- matériau de restriction invalide
- recette qui cible une table inconnue
- pattern trop grand
- lignes de pattern de tailles différentes
- symbole utilisé mais non déclaré
- recette sans résultat alors qu'elle doit en donner un

Les ingrédients déclarés mais non utilisés sont des warnings, pas des erreurs.
