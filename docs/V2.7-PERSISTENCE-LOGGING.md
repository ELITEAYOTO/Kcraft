# KCraft V2.7 — Persistence / Logging

## Logging avant

Chaque craft pouvait créer un `runTaskAsynchronously` individuel.
`writeLogEntry()` ne persistait rien : TODO/debug seulement.
`savePlayerStats()` était également TODO.

## Logging V2.7

```text
craft
 -> capture Bukkit main-thread
 -> CraftLogRecord pur Java
 -> ConcurrentLinkedQueue
 -> 1 worker async toutes les 40 ticks
 -> batch <= 500
 -> append JSONL
```

Aucun Bukkit Player/World/Location n'est lu depuis le worker async.

Queue max : 10 000 records. Au-delà, le record détaillé est dropped mais les
stats agrégées restent comptées.

Shutdown : drain complet synchrone pour garantir zéro perte.

## Stats

Réellement persistées :
- stats-global.json
- stats-players.json

Écriture temp + rename atomique quand supporté.

## Tables placées

Avant : chaque pose/casse réécrivait immédiatement tout placed_tables.json.

V2.7 :

```text
pose
pose
casse
pose
 -> markDirty x4
 -> 1 snapshot après 40 ticks
 -> 1 écriture async atomique
```

Si une modification arrive pendant l'I/O, une nouvelle génération est
reprogrammée après la fin du write.

onDisable appelle `savePlacedTables()` et force un flush final synchrone.
