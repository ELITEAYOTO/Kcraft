# KCraft V2.5 — GUI DirtyQueue + Preview Lock

## DirtyQueue

Avant :

```text
clic
clic
drag
shift-click inventaire
clic

=> 5 runTask/runTaskLater
=> 5 updateCraftResult
=> 5 RecipeIndex + RecipeMatcher
```

V2.5 :

```text
markDirty(uuid)
markDirty(uuid)
markDirty(uuid)
        |
        v
1 UUID dans LinkedHashSet
        |
        v prochain tick
1 flush
        |
        v
1 updateCraftResult
```

Le registre ne contient que des UUID.

Lors d'un close/quit/kick :
- UUID retiré de dirty ;
- preview retirée ;
- GUI libérée.

Le flush vérifie aussi que la GUI/session existe toujours avant de refresh.

## Preview Lock

Avant, pour une recette random :

```text
preview:
recipe.getResult() -> DIAMOND

clic:
recipe.getResult() -> COAL
```

Le joueur pouvait donc recevoir autre chose que ce qui était affiché.

V2.5 :

```text
updateCraftResult
  -> selection resultat
  -> PreviewSelection(uuid, recipeId, result)
  -> affiche result

clic
  -> même recipeId ?
  -> reutilise EXACTEMENT CraftResult verrouillé
```

Après une vraie tentative de craft :
- le lock est consommé ;
- le prochain refresh crée une nouvelle sélection.

Si `KcraftPreCraftEvent` est annulé :
- aucune tentative n'a eu lieu ;
- la preview reste verrouillée.

## Mass craft

Le premier craft d'un shift-batch reçoit exactement la preview affichée.

Les crafts 2..N tirent ensuite leurs résultats normalement, un par craft.

Cela évite de stocker 64 résultats aléatoires avant de savoir combien de
crafts réussiront réellement.
