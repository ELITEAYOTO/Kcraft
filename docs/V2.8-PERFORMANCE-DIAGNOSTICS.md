# KCraft V2.8 — Performance / Diagnostics

## Commandes

```text
/kcraft perf
/kcraft perf reset
/kcraft status
```

Permission : `kcraft.admin`.

## /kcraft perf

Affiche sans scan lourd :

- recipes / compiled / tables ;
- RecipeIndex buckets avg/max ;
- matching attempts/matches ;
- candidates et exact checks moyens ;
- temps matching avg/max ;
- NBT snapshots réellement initialisés ;
- batch plans / crafts planifiés / exécutés / failed / cancelled ;
- temps de planning batch ;
- GUI marks/coalesced/rate/refresh/stale ;
- dirty GUI / preview locks ;
- logging queued/written/pending/batches/dropped/failures ;
- queue max et temps I/O ;
- persistence tables writes/coalesced/failures.

## /kcraft perf reset

Remet uniquement les compteurs de diagnostic à zéro.

Ne touche pas :

- aux recettes ;
- aux tables ;
- aux logs présents sur disque ;
- aux stats gameplay ;
- aux GUI ouvertes.

## /kcraft status

État structurel :

- API V2 ;
- runtime config immutable ;
- cache legacy off ;
- RecipeCatalog / CompiledRecipeCatalog ;
- RecipeIndex ;
- Kfaction / Vault / PlaceholderAPI ;
- santé bridge KHopeSpigot ;
- stats globales de craft.

## Pourquoi un routeur KcraftCommandV2

On ne réécrit pas les ~700 lignes de `KcraftCommand` historique pour deux
sous-commandes.

`KcraftCommandV2 extends KcraftCommand` intercepte seulement `perf/status`
et délègue toutes les commandes historiques à `super`.

Cela réduit le risque de régression avant la phase fork.
